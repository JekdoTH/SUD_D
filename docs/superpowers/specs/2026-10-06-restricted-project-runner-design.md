### Proposed Mission and evidence contract

A Mission is finite authorization for one goal in one Workspace generation, not permanent Workspace Full Access. A Job is supervised execution within it; an Attempt is one budget-charged run; a Phase checkpoint is resumable project state bound to runner/input/artifact identities; a Final Artifact is verified retained bytes plus current QC evidence. Work Memory contains safe references to these facts, not executable authority.

The initial approval binds missionId/revision, goal/input digest, Workspace identity/generation, runner/code/dependency fingerprint, runtime/enforcement revision, fixed action/provider/network/secret profiles, allowed input uploads/output subtree/artifacts, resource/spend/retention limits, retry policy, expiry and cancel semantics. ### Decision and what this design resolves

**OS-SEPARATED CONTROL AUTHORIZATION DESIGN: BLOCKED.** Select a dedicated low-privilege own-process Windows control service as the candidate authority issuer. ### Conditional local protocol and authentication stop gate

This is a contract candidate, not a working authentication design. Secondary users/sessions do not share authority; no concurrent owner sessions/desktop installations adopt the active job.

The eventual application-specific control identity must protect code, grant issuance and keys against an ordinary same-user process, including launching a second genuine executable, modified JS/ASAR, DLL loading, injected code and stolen/duplicated pipe handles. ### Independent supervision and failure semantics

Service Recovery, guest heartbeat integration and automatic-stop-on-host-shutdown do not bind VM lifetime to helper lifetime. Proposed watchdog is a distinct own-process service with its own provider connection, read-only sealed enrollment, independent timer and forced-Off authority. It does not share helper locks/event loop or require helper answers to terminate. Before Start it durably records the armed epoch/lease and hard deadline and acknowledges readiness; a crash between arm and Start is reconciled by inspecting the slot, never assuming VM still Off. Watchdog never starts/resumes/replays jobs. Helper reciprocally forces-Off if watchdog disappears, before proceeding with further run activity.

Proposed disposable test constants, not measured guarantees: heartbeat every 1 s; liveness lease 5 s; supervisor check <= 250 ms; forced-Off observation deadline 10 s; total failure-to-Off acceptance deadline 16 s. Absolute job wall deadline <= 30 min from Begin, including boot; renewal cannot move it. Use a monotonic OS clock with documented suspend behavior; on sleep/resume, clock uncertainty or epoch discontinuity, stop/quarantine rather than granting a fresh lease. No restart may reconstruct an active lease as permission to run. Observe async Hyper-V operation result and VM Off: request submission, timeout return or stopped helper process is not termination evidence. `RequestStateChange.TimeoutPeriod` is unused; it is not an enforced kill deadline.

| Failure | Required response |
| --- | --- |
| Helper crash/hang | Independent watchdog observes process/liveness loss and forces exact slot Off within 16 s; dirty state quarantined; admission closed. |
| Watchdog crash/hang | Helper detects missing supervision, forces-Off and quarantines; cannot keep running or re-arm through service auto-restart. |
| Desktop crash/logout | Owner/control session expiry ends lease; helper/watchdog stop. Do not let surviving gateway heartbeat stand in for Desktop intent. |
| Gateway crash/replacement | Original gateway session expires; stop, no replacement adoption/replay. |
| Broker crash/stall | Protected broker readiness/liveness fails; stop, bounded drain/cancel, no success publication. |
| ChatGPT disconnect / explicit Disconnect | Lose connection intent/liveness, stop within deadline. Ending a turn while the same live connection remains healthy is not disconnect. A missing authoritative connection-loss signal is BLOCKED, not guessed from pipe activity. |
| Host shutdown/reboot/power loss | AutoStop=TurnOff, AutoStart=Nothing; boot services reconcile before admission, reject saved state, stop leftovers, preserve charged dirty data. Power loss does not prove disk cleanup. |
| Helper restart/update/SCM recovery | Fence epoch, stop/quarantine before Ready; no auto VM start/resume or job replay. |
| Both services fail, vmms/provider hangs, host scheduling stops | Two user-mode services provide no established universal finite-Off guarantee. Keep admission closed, including after restart; do not label quarantine as stopped. No automatic reboot, killing arbitrary VMWP/VMMS or third privileged scheduler is authorized. This limitation does not replace the mandatory independent single-helper-failure proof or silently expand it into an all-host-failures guarantee. |

Independent single-helper failure is the mandatory proof, including a helper hang with Desktop unavailable. For combined supervisor/provider failure, the task permits blocked new admission; it does not permit claiming the VM is Off. State this residual limitation explicitly. Blocking admission alone cannot substitute for the mandatory helper-failure termination proof. ## Approval, fingerprint and reviewed details

For each start, prepare an immutable snapshot before asking. If changed, expire reservation/grant and require new Approval; never silently launch the old approved snapshot against changed project state. ### Bounded artifact-stream-v1 protocol candidate

Fixed **24-byte little-endian header**: magic SDB1 (4 bytes), version u16 (=1), kind u16, payloadLength u32, artifactOrdinal u32, sequence u32, flags u32 (=0). No pointer fields, signed lengths or fallback negotiation. Validate header/state/limits **before** payload allocation/read; reject unknown version/kind/flags, wrong sequence or overflow. Sequence starts 0, increments per frame, cannot wrap. Arbitrary transport splits/coalescing require incremental exact-length reads, not one read = one frame.

| Kind | Payload / legal state |
| --- | --- |
| START | First only; ordinal 0; closed strict UTF-8 JSON <=4 KiB with protocol, expected job/attempt/fingerprint matching approved host context. Claims are not authentication. |
| META | <=1 KiB closed JSON `{declaredId,mediaType,expectedLength?}`; ordinal = approved declaration slot 1..50. ID/type match approval; length is bounded claim. One open artifact, one META per ID. No path/name/URL/env/command/FS operation. |
| CHUNK | 1..65,536 raw bytes for open ordinal. Check per-artifact/total budgets before acceptance/write. No offsets, seek, holes, compression/decompression, base64 or caller transform. |
| END | Zero payload; closes current artifact and verifies claimed length if present; completes host hash/length validation. META then END permits a zero-byte artifact, consuming one slot. |
| JOB_END | Ordinal 0; <=1 KiB closed JSON with optional approved QC claim only (enum verdict, <=128-character code). All artifacts closed, required IDs present; optional IDs may be absent. Marks protocol complete, **not success**. EOF must follow; any trailing byte fails. |
| ERROR | Ordinal 0; <=256-byte closed JSON fixed enum failure code; whole-attempt failure. No raw exception/message/path. |

No runner CANCEL frame controls Jobs; ERROR fails this attempt only. Host cancellation is OS Job termination/reader cancellation, not a responsive stdin request. Metadata JSON rejects duplicate/unknown keys, malformed UTF-8, nonfinite/unsafe integers, controls and excessive depth after bounded framing. CHUNK is binary, never text-decoded. Missing/out-of-order/duplicate/nested frames/IDs, partial EOF, oversized payload or wrong ordinal are fatal: terminate Job, quarantine all, no resync.

Additional candidate host-profile caps: <=20,000 frames, <=64 KiB cumulative metadata payload, <=66 MiB wire bytes (headers included), <=10 s idle/frame deadline plus approved total wall timeout. Thus empty/control-frame floods have byte/count/time limits. Legitimate workloads must fit both payload and frame limits; huge/many tiny-chunk workloads fail honestly. Constants or approved reductions only, not caller tuning.

Pre-Resume fault executes zero project code; post-launch fault cancels held Job. Stop/timeout/shutdown fence completion transaction; winning termination intent prevents late success. Success requires valid protocol through JOB_END/EOF, root exit 0, Job active count 0, both readers done, no cancellation/IO/cleanup uncertainty and all required evidence. Root exit, EOF and JOB_END independently are insufficient. Descendants retaining handles keep it nonterminal until deadline/termination.

Reuse starting/running/terminal states and bounded safe codes: artifact-invalid for protocol/evidence, resource-limit for budgets, runtime-unavailable for IO/runtime and cleanup-unconfirmed for uncertain ownership. Required DB/audit failure cancels even if persistence is unavailable; never fabricated success. Disconnect/tunnel/gateway loss, switch/quit/update use existing fenced drain plus broker IO-empty. Only after tree/readers/writers close can Desktop transition. Crash relies on final Job-handle close killing descendants, then interrupted reconciliation without replay. Public status/artifact access remains Workspace-guarded and hides private paths; no automatic Team/checkpoint changes.
