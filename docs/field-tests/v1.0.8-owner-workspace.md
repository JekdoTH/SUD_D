- [Process adapter](https://github.com/JekdoTH/SUD_D/blob/v1.0.8/packages/infrastructure/src/restricted-verify-adapter.ts): reviewed package script through host Node and fixed package-manager CLI, allowlisted environment, `shell:false`, 300,000 ms default timeout, 32,768 captured bytes, redaction and best-effort process-tree termination. Git checks use the Git adapter instead of a project package script.
- [Discovery](https://github.com/JekdoTH/SUD_D/blob/v1.0.8/packages/application/src/project-runner-discovery.ts) and [manifest parser](https://github.com/JekdoTH/SUD_D/blob/v1.0.8/packages/infrastructure/src/runner-manifest.ts): empty discovery input, validated version-1 Workspace manifest, supported `node-offline-v1` metadata and `executionAvailable: false`; no import/execution of the runner.

The package-manager declaration selects a supported CLI profile; it is not proof that the declared version was automatically installed or verified. Scripts/dependencies need owner review. They run with host-user permissions; this is not OS-enforced file/network containment. Approval is action/context authorization, not a guarantee that arbitrary project code is safe or an authorization for an entire future workflow. Output redaction and a successful exit code do not substitute for workflow-specific QC.

Host prerequisites and the optional prompt template are in [README](../../README.md#quick-start--field-test). Missing script/runtime/profile must be reported, not worked around by weakening gates.
