# Security Policy

## Reporting a vulnerability

Please report security vulnerabilities privately through GitHub's private vulnerability reporting / Security Advisory flow for this repository when available.

Do **not** include credentials, API keys, tunnel identifiers containing sensitive access material, signing private keys, private user data, or exploitable proof-of-concept secrets in a public issue, discussion, pull request, or log excerpt.

If private GitHub reporting is temporarily unavailable, contact the repository maintainers through a private channel associated with the repository owner rather than publishing the vulnerability details publicly.

A useful report includes the affected version or revision, the security boundary involved, reproduction steps that do not expose unrelated private data, and the expected versus observed behavior.

## Supported versions

Until a broader support policy is published, security fixes target the current stable release line. v1.0.0 establishes the permanent release-signing trust root for subsequent in-app updates.
